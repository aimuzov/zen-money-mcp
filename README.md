# zen-money-mcp

MCP-сервер для [ZenMoney](https://zenmoney.ru), который помогает **проверять и
исправлять категории расходов**.

ZenMoney при синхронизации с банком ставит категорию по принципу «какая была
последней у этого мерчанта». Это часто неверно: в одном магазине вы в разные дни
покупаете то пиво, то продукты, а проставляется одно и то же. Этот сервер
анализирует вашу историю, находит расходы с сомнительной или отсутствующей
категорией, отдаёт Claude обоснованные кандидаты — а вы подтверждаете правку,
которая записывается обратно в ZenMoney.

## Как это работает

```
Claude ──MCP/stdio──▶ zen-money-mcp ──HTTPS──▶ ZenMoney POST /v8/diff/
                            │
                            ▼
                   локальный кэш (node:sqlite)
            вся история, инкрементальная синхронизация
```

- Вся история ZenMoney тянется один раз в локальный кэш SQLite, дальше —
  инкрементально.
- Категорию **не выбирает сам сервер**. Он считает по истории места
  (мерчант → нормализованный payee → MCC) ранжированных кандидатов с
  «уверенностью», взвешивая по свежести, дню недели и диапазону суммы — а решение
  принимает Claude в диалоге (гибридный подход).
- Запись — только через явное подтверждение: инструмент записи по умолчанию
  работает в режиме превью (`dryRun: true`).

## Требования

- **Node.js ≥ 24** (используется встроенный модуль `node:sqlite`, нативная
  компиляция не нужна).
- **pnpm**.
- OAuth-приложение ZenMoney: зарегистрируйте его на
  [developers.zenmoney.ru](https://developers.zenmoney.ru) (или `.app`) и получите
  `consumer key` / `consumer secret`. В настройках приложения укажите
  **redirect URI**: `http://localhost:53682/callback` (порт можно изменить через
  `ZEN_REDIRECT_PORT`).

## Установка и сборка

```bash
pnpm install
pnpm build
```

## Настройка окружения

Скопируйте `.env.example` в `.env` и заполните:

```bash
ZEN_CLIENT_ID=...          # consumer key
ZEN_CLIENT_SECRET=...      # consumer secret
ZEN_ENDPOINT=ru            # ru или app
ZEN_REDIRECT_PORT=53682    # должен совпадать с redirect URI приложения
# ZEN_DATA_DIR=            # где хранить кэш и токен (по умолчанию ~/.config/zen-money-mcp)
```

## Авторизация (один раз)

```bash
pnpm auth
```

Откроется браузер, вы войдёте в ZenMoney и подтвердите доступ. Токен сохранится в
`~/.config/zen-money-mcp/auth.json` (права `0600`) и дальше будет обновляться
автоматически.

## Первая синхронизация

```bash
pnpm sync          # инкрементально (или всё с нуля при первом запуске)
node build/index.js sync --full   # принудительно перетянуть всю историю
```

## Подключение в Claude Code

Добавьте сервер в `.mcp.json` (см. `.mcp.json.example`):

```json
{
  "mcpServers": {
    "zen-money": {
      "command": "node",
      "args": ["/absolute/path/to/zen-money-mcp/build/index.js"],
      "env": {
        "ZEN_CLIENT_ID": "...",
        "ZEN_CLIENT_SECRET": "...",
        "ZEN_ENDPOINT": "ru"
      }
    }
  }
}
```

Авторизацию (`pnpm auth`) всё равно нужно выполнить один раз в терминале — stdio-
сервер сам браузер не открывает; если токена нет, инструменты вернут понятную
подсказку запустить `auth`.

## Инструменты

| Инструмент | Назначение |
|---|---|
| `zen_sync` | Обновить локальный кэш из ZenMoney |
| `zen_list_categories` | Дерево категорий (тегов) с путями |
| `zen_find_transactions` | Гибкий поиск (период, счёт, без категории, «под вопросом», мерчант/payee/MCC) |
| `zen_merchant_history` | Полный разбор истории по мерчанту/payee/MCC |
| `zen_review_expenses` | **Аудит**: расходы без категории или с подозрительной категорией + кандидаты |
| `zen_apply_categories` | Запись изменений (по умолчанию `dryRun` — сначала превью) |

### Типичный сценарий

> «Проверь мои расходы за прошлую неделю»

Claude вызовет `zen_sync` → `zen_review_expenses` → предложит исправления →
`zen_apply_categories {dryRun:true}` покажет before → after → после вашего «да»
вызовет `{dryRun:false}` и запишет.

## Заметки по реализации

- Время везде хранится в Unix-секундах (без конвертации в миллисекунды, в отличие
  от референсного клиента zerro).
- Хранилище — встроенный `node:sqlite` (выбран вместо `better-sqlite3`, чтобы не
  зависеть от нативной компиляции под свежий ABI Node).
- Реализованы фазы 1–2 (фундамент + аудит с записью). Фаза 3 (дневной дайджест и
  советы, `zen_daily_summary`) — запланирована отдельно.
